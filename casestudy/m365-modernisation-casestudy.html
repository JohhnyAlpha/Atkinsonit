Microsoft 365 Modernisation Case Study

A case study by Atkinson IT Ltd

Overview

A UK‑based SME approached Atkinson IT with a familiar challenge: a Microsoft 365 environment that had evolved over several years, carrying legacy domains, outdated identity structures, and incomplete security controls. Although functional, the system had accumulated friction — inconsistent login behaviour, outdated security, and branding drift.

Two lines from the audit captured the situation clearly:

“The environment shows signs of legacy configuration, outdated identity structure, and incomplete security posture.”

“The tenant still uses a legacy domain as its default.”

The business wanted a system that was secure, predictable, and aligned with its current identity — something that just works across PC, laptop, and phone.

Initial challenges

1. Legacy domain still set as default

The Microsoft 365 tenant still treated an old domain as primary. This affected login behaviour, DKIM alignment, email routing, and branding consistency.

2. Fragmented identity structure

The main user had three separate identities across different domains, including an internal onmicrosoft.com address and a legacy Gmail technical contact. This caused duplication and inconsistent login behaviour.

3. Outdated security posture

MFA was not enabled. Conditional Access was not configured. Legacy protocols (POP/IMAP/SMTP AUTH) were still active. These left the business vulnerable to password‑based attacks, phishing, and account compromise.

4. DNS hosted on a legacy platform

DNS was still hosted on a registrar rather than a modern DNS provider, limiting stability, security, and email authentication performance.

5. Devices not registered or updated

Office apps were out of date, devices were not Azure AD joined, and no compliance baseline existed.

Modernisation approach

Atkinson IT delivered a structured 4‑day modernisation, combining offsite foundational work with onsite device alignment.

Day 1 — DNS migration & identity correction (Offsite)

  • Migrated DNS to Cloudflare
  • Switched nameservers
  • Verified MX/SPF/DMARC
  • Set the correct business domain as default
  • Consolidated user identities
  • Retired unused legacy addresses
  • Fixed Authenticator setup
  • Tested login behaviour across devices

Outcome: A clean identity structure and Cloudflare as the single source of truth for DNS.

Day 2 — Email security alignment (Offsite)

  • Regenerated DKIM
  • Added new selectors to Cloudflare
  • Enabled DKIM once DNS propagated
  • Confirmed SPF/MX/DMARC alignment
  • Checked for residual legacy artefacts

Outcome: Modern, trusted email authentication aligned with the business identity.

Day 3 — Security modernisation (Offsite)

  • Enabled MFA for all users
  • Created baseline Conditional Access policies
  • Blocked legacy authentication
  • Tested secure login across devices

Outcome: A Zero‑Trust baseline replacing legacy security.

Day 4 — Device updates, cleanup & final review (Onsite)

  • Fixed Authenticator on mobile devices
  • Cleaned Outlook profiles
  • Removed cached legacy credentials
  • Registered devices in Azure AD
  • Ran Windows & Office updates
  • Offboarded unused accounts
  • Removed legacy groups and artefacts

Outcome: All devices aligned with the new identity, security, and domain configuration.

Final result

The SME now operates on a stable, modern, future‑proof Microsoft 365 foundation:

  • One clean identity structure
  • Correct domain hierarchy
  • Cloudflare DNS with aligned DKIM
  • Modern security (MFA, CA, no legacy auth)
  • Updated devices with consistent login behaviour
  • Legacy artefacts removed
  • A tenant designed to last decades without major rework

Frequently asked questions

How disruptive is a Microsoft 365 modernisation?

With structured planning, identity cleanup, and staged device alignment, most SMEs experience minimal disruption.

Do legacy domains cause long‑term issues?

Yes — they affect login behaviour, DKIM alignment, branding, and email trust. Correcting domain hierarchy is essential.

Is MFA and Conditional Access really necessary?

Absolutely. They form the backbone of modern Zero‑Trust security and protect SMEs from common attack vectors.
