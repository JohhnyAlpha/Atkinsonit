Disaster Recovery & Business Continuity Case Study

A Case Study by Atkinson IT Ltd

Overview

A division of a FTSE100 organisation suffered a sudden and severe disaster when a building‑work incident in an adjacent property caused water ingress into one of its two server rooms. The incident drenched the IBM Tivoli TSM tape subsystem, destroying the onsite copy of all backups and rendering the room unusable.

With no operational backup system and critical data at risk, the organisation required a fully functional backup and recovery strategy within 48 hours.

The Challenge

  • The entire IBM robotic tape library was destroyed
  • All onsite backup copies were lost
  • The server room was unusable due to water damage
  • Critical systems had no recovery path
  • Replacement hardware would take months to procure
  • The business required immediate DR/BCP capability
  • Environment included hundreds of servers and multidomain authentication

This was a genuine business‑critical emergency.

Constraints

  • A working backup solution had to be operational within 2 working days
  • Critical systems needed protection first
  • The remaining server room had limited capacity
  • The new tape library would take months to commission
  • Solution had to support Windows, Linux, VMware, and multidomain file services
  • Final design needed to support long‑term DR/BCP

What I Did

I designed and deployed an emergency NetApp‑based backup and recovery platform, then oversaw the design and commissioning of a new multi‑cabinet IBM tape library and a long‑term DR/BCP architecture.

1. Emergency NetApp Backup Platform (48‑hour deployment)

To restore backup capability immediately:

  • Deployed a NetApp storage system as a temporary backup target
  • Configured high‑capacity aggregates for rapid ingestion
  • Integrated with existing servers and VMware hosts
  • Enabled snapshots for instant recovery
  • Implemented SnapMirror for offsite replication
  • Prioritised critical systems for first‑wave protection

This restored backup capability within the 2‑day deadline.

2. Critical‑First Migration

I triaged systems into tiers:

Tier 1 — Critical

  • Financial systems
  • Authentication services
  • Core databases
  • Line‑of‑business applications
  • VMware management infrastructure

Tier 2 — Important but not business‑critical

  • Departmental file shares
  • Secondary applications
  • Internal web services

Tier 3 — Low priority

  • Archive data
  • Legacy systems
  • Non‑production workloads

This ensured the business regained resilience as fast as possible.

3. New Tape Library Design & Commissioning

I oversaw the design of a newly commissioned server room and the installation of a:

  • Multi‑cabinet
  • Robotised
  • IBM tape library
  • Integrated with Tivoli TSM
  • With redundant power, cooling, and fire suppression

This multi‑month project included:

  • Rack layout
  • Fibre Channel zoning
  • Power distribution
  • Environmental controls
  • Tape robot calibration
  • Integration with the NetApp platform

Once operational, it became the long‑term archival tier.

4. Reverse Migration & DR Architecture

When the new tape subsystem was fully functional:

  • Backups were migrated back to the tape library
  • The NetApp system was repurposed offsite
  • SnapMirror replication was configured for DR
  • A tertiary DR site was established for cold‑standby BCP
  • Regular failover tests were implemented

This created a three‑tier resilience model:

  • Local snapshots (instant recovery)
  • Tape library (long‑term retention)
  • Offsite NetApp (DR/BCP replication)

Outcome

  • Full backup capability restored within 48 hours
  • Zero data loss despite the disaster
  • Critical systems protected first
  • New enterprise‑grade tape library commissioned successfully
  • Offsite DR replication established
  • Long‑term BCP architecture implemented
  • Improved RTO/RPO across all systems
  • A more resilient, modern, multi‑tier backup strategy

This transformed a near‑catastrophic incident into a robust, future‑proofed DR/BCP solution.
